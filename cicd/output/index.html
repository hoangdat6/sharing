05 / Bản chất CI

Continuous Integration (CI) là gì?

Continuous Integration (Tích hợp liên tục) là thực hành phát triển phần mềm mà các thành viên thường xuyên tích hợp mã vào kho chung. Mỗi lần tích hợp được tự động xác minh bằng build & test độc lập để phát hiện lỗi sớm nhất có thể. Martin Fowler — continuousintegration.martinfowler.com

Bản chất độc lập

CI là hệ thống kiểm tra tự động tách biệt hoàn toàn với máy cá nhân — đảm bảo mọi thay đổi được xác minh trên môi trường sạch trước khi merge.

03

Hệ thống CI (Automated Runner)

Chấm độc lập trên Runner sạch — Kiểm tra tự động 100% khách quan trước khi Merge.

02

Code Review (Peer Review)

Đồng nghiệp xem PR — Đánh giá kiến trúc, logic nghiệp vụ & thiết kế giải pháp.

01

Tự kiểm tra (Dev / AI)

Lập trình viên / AI tự chạy test trên máy local — Tự chấm bài bằng tư duy chủ quan.

10 / Bản chất CD

Continuous Delivery / Deployment là gì?

01 / Bản chất CD

Đưa đúng Artifact đã test ra Server

CD không biên dịch hay build lại code trên server. CD tiếp nhận đúng Docker Image kèm tag Git Commit SHA đã được CI xác minh để triển khai.

02 / Nhiệm vụ CD

Tự động hóa chuỗi thao tác Release

Thay thế thao tác SSH & gõ lệnh thủ công bằng quy trình tự động: Tải Artifact → Cấu hình → Khởi chạy Container → Kiểm tra Health Check.

FETCH ARTIFACTpull image:sha

18 / Phần 7

Các issues có thể phát sinh khi Deploy

Đã có CI/CD vẫn có thể deploy lỗi — nếu pipeline cấu hình chưa chặt. Đây là các điểm trượt thường gặp trong quá trình CI/CD, trước khi code chạm Production.

01

Môi trường CI ≠ Local

Runner/container khác OS, runtime, dependency và config với máy dev — local xanh, pipeline đỏ (hoặc ngược lại).

02

Test sai phạm vi / code ẩn

Chỉ test file vừa sửa, code chưa commit, checkout sai ref — pipeline pass nhưng không phải bản sẽ deploy.

03

Pipeline lỗi nhưng vẫn deploy

continue-on-error, thiếu needs, bypass branch protection — job deploy chạy dù CI fail.

Issue 04 — Giai đoạn CD

Deploy image tag :latest — không biết đang chạy commit nào, ghi đè version, rollback khó hoặc không thể.

20 / Phần 7 · Issue 02

Test sai phạm vi — Pipeline pass nhưng deploy sai code

ISSUE ẨN: CI báo xanh nhưng không đảm bảo bản build = bản sẽ lên server — do phạm vi test hẹp hoặc artifact không khớp commit.
A

Chỉ test file vừa sửa

vitest src/foo.test.ts thay vì full suite — side-effect ở module khác không bị quét.

B

Code chưa commit

Local test pass với file chưa push — CI checkout remote không có file đó, hoặc ngược lại.

C

Checkout sai ref

Workflow test nhánh main trong khi PR merge từ feature — test không phải diff sẽ deploy.

D

Config ẩn chỉ có trên máy dev

.env.local, symlink, global package — có trên laptop, không có trên runner.

ISSUE 02: PIPELINE XANH KHÔNG ĐỒNG NGHĨA ĐÚNG CODE SẼ DEPLOY20 / 24

21 / Phần 7 · Issue 03 & 04

Pipeline lỗi vẫn deploy & Tag :latest

Issue 03 — CI fail nhưng CD vẫn chạy

  • continue-on-error: true trên step quan trọng
  • Job deploy không needs: [ci]
  • Branch protection tắt / admin bypass merge
  • Chỉ xem icon xanh tổng thể, không đọc log job fail
Workflow “xanh” nhưng step test/build đã fail — deploy vẫn đẩy image lên server.

Issue 04 — Deploy tag :latest

  • Ghi đè tag liên tục — mất dấu SHA
  • Rollback = đoán version, không pull chính xác bản cũ
  • 2 lần deploy liên tiếp — không biết lần nào gây lỗi

22 / Phần 8

Cách khắc phục các issues đó trước khi Deploy

Chặn ở cấu hình pipeline — trước merge, trước khi image chạm server. Mỗi issue Phần 7 có biện pháp tương ứng.

Issue → Khắc phục

  • Môi trường CI ≠ local → Container sạch + ghim runtime + npm ci
  • Test sai phạm vi → Full test suite + checkout đúng ref + script chuẩn
  • Pipeline lỗi vẫn deploy → needs + branch protection + fail-fast
  • Tag :latest → Immutable tag theo ${{ github.sha }} + health check
Deploy chỉ được phép khi CI pass thật trên đúng commit — và image phải trace được về SHA cụ thể. Phần 8 — Khắc phục trước Deploy

23 / Tổng kết

Tầm quan trọng của CI & CD

CI và CD là hai mắt xích bổ sung nhau — không thay thế nhau. AI có thể sinh code nhanh, nhưng chỉ pipeline mới đảm bảo chất lượng và phát hành có kiểm soát.

CI — Continuous Integration

Đảm bảo chất lượng

  • Kiểm tra tự động trên runner độc lập — không tin máy local hay lời AI
  • Gate trước merge: lint, typecheck, test, build phải pass
  • Phát hiện lỗi sớm, rẻ — trong sandbox, chưa ảnh hưởng user
  • Tiêu chuẩn chung cho cả team: cùng lệnh, cùng môi trường

CD — Continuous Delivery / Deployment

Đưa bản đã kiểm tra lên server

  • Chỉ deploy artifact/image đã pass CI — needs nối CI với CD
  • Tag immutable theo commit SHA — biết chính xác version đang chạy
  • Quy trình lặp lại được, audit được — không SSH thủ công
  • Rollback nhanh về bản cũ khi có sự cố trên Production
CI trả lời câu hỏi "Code này có đủ chuẩn không?" — CD trả lời "Bản đã kiểm tra này có lên server an toàn không?" Tổng kết — Kaopiz Sharing
